# 2026-10-24 — Legacy Synth sound: swarm at the analog circuit level, new OSD names

## Symptom

With the OSD sound set to the FBNeo version, the user found the swarm hum
(the "웅웅" rack noise, FS1-FS3) much quieter than with the discrete sound.
FBNeo itself sounds the same, so the FPGA block was correct; the user asked
for the swarm to play at about the same volume as the discrete sound, so that
switching the option changes the timbre but not the balance.

They also asked for option names that are not emulator names.

## Cause

FBNeo's Galaxian sound (a port of the MAME 0.36b11 - 0.133u1 synthesized
sound) mixes the swarm with a hand-chosen constant: `LFO_VOLUME 0.06f`
against `TOOTHSAW_VOLUME 0.36f` for the tone. One swarm channel is +244 / -248
in a 16 bit output (all three on: +-744). This value was a mixing choice in
old MAME, not a measurement of the PCB.

Measured with the C++ models on the same MAME register logs (first 100 s,
K-weighted RMS while the channel is active, 20 Hz - 20 kHz):

| game (mixer) | swarm, discrete | swarm, FBNeo | difference | other sounds, discrete - FBNeo |
|---|---|---|---|---|
| Galaxian | -20.6 dBFS | -37.6 | 17.0 dB | +0.8 dB |
| UniWar S | -21.5 | -38.5 | 17.0 | +2.0 |
| Azurian Attack | -20.7 | -37.7 | 17.0 | +1.8 |
| War of the Bugs | -22.6 | -39.6 | 17.0 | -0.6 |
| Catacomb | -20.9 | -38.0 | 17.1 | +0.5 |
| Black Hole | -22.1 | -39.3 | 17.2 | +5.6 |
| King & Balloon (Moon Cresta mixer) | -26.3 | -37.6 | 11.3 | +3.3 |

* Tone, fire and explosion are already within about 2 dB between the two
  blocks; only the swarm is far off.
* The swarm difference is the same in every game on the Galaxian mixer
  (17 dB = x7.1). King & Balloon uses the Moon Cresta output mixer in the
  discrete model (`I_MOONCR`), where the swarm is quieter: 11.3 dB = x3.7.
* So no per-game table is needed: one factor per mixer, selected by the
  signal that already selects the discrete block's mixer (`W_MOONCR`:
  King & Balloon, Moon Quasar, Port Man).
* Games that never turned the swarm on in 150 s of MAME autoplay (not
  affected): Orbitron, Devil Fish, Moon Quasar, Port Man, Victory, Pisces,
  Moon Cresta (Galaxian hardware). Not checked: Lucky Today (no sound writes
  in MAME), Clean Sweep and Mr. Do Nightmare (not in MAME).

## Why there are two Galaxian sounds (research for the option names)

Both are emulations of the same circuit, not board revisions:

* before MAME 0.36b11: recorded samples (recorded from cabinets in use and
  hand edited, not trusted as a reference by MAME developers);
* MAME 0.36b11 - 0.133u1 (~2000-2009): each sound synthesized directly, the
  circuit only approximated; FBNeo `gal_sound.cpp` is a port of it;
* MAME 0.133u2+ (2009, couriersud): discrete netlist with the real part
  values.

Videos of real boards differ from each other because the analog parts vary:
"sound varies from board to board quite considerably" (Mike Coates, quoted in
MAME Testers #03109), and Galaxian boards with different hum speeds are
reported in MAME Testers #00443. No source compares the old synthesized
swarm volume with a PCB.

Sources: https://mametesters.org/view.php?id=443,
https://mametesters.org/view.php?id=3109,
https://mail.misterfpga.org/viewtopic.php?p=44134

## Fix

* `rtl/galaxian_snd_fbn.vhd`: new input `I_MOONCR`; swarm wave levels
  +1537 / -1562 (x6.3, Galaxian mixer) or +813 / -826 (x3.33, Moon Cresta
  mixer) instead of +244 / -248. Everything else is unchanged (tone, fire and
  explosion are still sample-identical to before).
  The first build used the measured match, x7 / x3.7 (+1708 / -1736,
  +903 / -918). After listening on MiSTer the user asked for the hum 10 %
  quieter, so the factors are 0.9 times that (-0.9 dB below the analog
  circuit level).
* `rtl/galaxian.vhd`: `W_MOONCR` connected to the block.
* `Arcade-Galaxian.sv`: OSD `O7,Sound,Analog Circuit,Legacy Synth;`
  (was `Discrete (MAME),Classic (FBNeo)`), same status bit, same default.
* Sim tools: `fbn_fix.cpp` (new argument `[audio.raw|-] [mooncr]`),
  `tb_galaxian_snd_fbn.vhd` (generic `MOONCR`), `vl_tb_fbn.cpp`
  (argument `[mooncr]`). `fbn_ref.cpp` stays FBNeo as-is, so its swarm
  channel is now intentionally 7x (3.7x) quieter than the RTL.

## How it was verified

1. `tb_galaxian_snd_fbn` (GHDL) == `fbn_fix`, bit identical, 400 ms dense
   stimulus, MOONCR = 0 and 1 (sample watchdog on, 10 min limit).
2. Verilator (`vl_fbn.sh`) == `fbn_fix`, bit identical: 60 s Galaxian
   (mooncr 0) and 60 s King & Balloon (mooncr 1).
3. Swarm only output: old +240 / -252 / +732 / -744 -> x7 build +1680 /
   -1764 / +5124 / -5208, x3.7 build +888 / -933 / +2709 / -2754; final
   (-10 %) +1512 / -1587 / +4611 / -4686 and +800 / -839 / +2439 / -2478.
   Tone channel identical to the previous model.
4. Levels again with the x7 / x3.7 build vs discrete: swarm within
   0.1-0.3 dB (K-weighted) in all 7 games, so the final values are 0.9 dB
   below the discrete level. Peaks: 3 games touch the 16 bit limit in 1-2
   samples per million (explosion + swarm), not audible.
   Steps 1-2 were repeated, bit identical, after the -10 % change.
5. Full core with the Galaxian ROM (`tb_core`, `CLASSIC=1`,
   `STUB_DISCRETE=1`): 1.8 s, 107 frames, no metavalues, VSYNC watchdog quiet
   (output silent as expected this early, see fixes-2026-10-23.md).
6. Quartus 17.0 debug build (final -10 % values): 0 errors, 40 % ALMs,
   23 % block memory, 59/112 DSP (same as before). 4 corner timing
   (`quartus_sta --multicorner=on`): no negative slack, worst hold
   +0.074 ns, worst setup +0.221 ns (HDMI PLL clock in the MiSTer framework;
   the x7 build had +0.633 ns there, placement varies between builds).

Status: the debug build is on MiSTer as `Galaxian_20261024.rbf`; listening
test on the real hardware (OSD Sound = Legacy Synth, Galaxian and
King & Balloon) pending.

Side effect to know: in Black Hole the other sounds are 5.6 dB quieter in
Legacy Synth than in Analog Circuit (FBNeo's own balance), so there the swarm
is about as loud as the other sounds (-0.1 dB with the final values; -4.5 dB
in the discrete sound). Left as is: only the swarm level was in scope.

Correction to fixes-2026-10-23.md item 8: that timing check was slow corner
only (the MiSTer project has multi-corner analysis off). A 4 corner
`quartus_sta --multicorner=on` run on that build also passed; worst slack
+0.078 ns (hold, fast -40C), not +0.224 ns.
