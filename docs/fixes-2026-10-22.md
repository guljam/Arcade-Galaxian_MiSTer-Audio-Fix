# 2026-10-22 — Galaxian sound rewritten after MAME's discrete netlist

## Symptom

Galaxian (Namco, Set 1) sounded very different from the arcade board and from
MAME:

* the alien "swarm" background sound was a smooth sine-like tone;
* the swarm rhythm, which speeds up as a stage goes on, felt wrong: too fast
  at the start of a stage and not speeding up the way MAME does.

## Cause

The old sound (`rtl/mc_sound_a.vhd`, `mc_sound_b.vhd`, `mc_sound_vco.vhd`,
`sine_package.vhd`, `ROM/FIR.vhd`, `ROM/HIT.vhd`) was a rough approximation of
the analog board:

| Part | Real board / MAME | Old core |
|---|---|---|
| Swarm oscillators (8R/8S/8T) | three 555 astables, pulse output through a 10k/10k/10k mixer and C20 low pass | three sine table VCOs |
| Swarm LFO | 4 bit R-ladder DAC sets the current of a 555 constant-current sawtooth (1 uF); the sawtooth drives the 555 control voltages | linear counter `step = (not DAC) + 4`, lookup table of 32 steps |
| Fire | 555 VCO, control voltage = noise + RC sweep (47 uF), RC envelope | fixed recorded sample (FIR ROM) |
| Explosion (HIT) | LFSR noise sampled at 2V, RC envelope (2.2 uF), op-amp band pass 168 Hz with rail clipping | fixed recorded sample (HIT ROM) |
| Mixer | resistor network, VOL1/VOL2 switch resistors in and out, C26/C46 coupling caps | sum of 8 bit numbers |

The rhythm problem is the LFO. The game counts the DAC down from 15 to 0
during a stage (one step about every 4.2 s). On the board the charge current
is `(5 V - 0.7 V - Vdac) / 100k`, and the DAC resistors (1M/470k/220k/100k) are
not binary weighted, so the LFO period is non-linear in the DAC value:

| DAC | 15 | 14 | 13 | 12 | 11 | 8 | 4 | 0 |
|---|---|---|---|---|---|---|---|---|
| MAME / new core (s) | 1.248 | 0.930 | 0.722 | 0.602 | 0.488 | 0.344 | 0.227 | 0.177 |
| old core (s) | 0.699 | 0.559 | 0.466 | 0.399 | 0.350 | 0.254 | 0.186 | 0.147 |

## Hypothesis

MAME sounds close to the arcade board because its discrete netlist simulates
the actual circuit (555 timers, RC networks, op-amp filter, resistor mixer)
with the real component values. If the FPGA computes the same circuit
equations, with the same component values, it should sound like MAME, and
the swarm rhythm should follow automatically from the non-linear LFO. This
can be checked numerically: log the sound register writes in MAME, feed the
same writes to a model of the RTL, and compare the audio with MAME's WAV.

## Fix

New sound block `rtl/galaxian_snd.vhd` (+ generated constants
`rtl/galaxian_snd_pkg.vhd`) that models the analog circuit the same way MAME's
`galaxian_discrete` / `mooncrst_discrete` netlists do (`src/mame/galaxian/galaxian_a.cpp`).
Note: Galaxian in MAME uses the *discrete* sound core, not netlist.

* Every MAME node has a matching block; comments in the VHDL name the node
  (NODE_105 LFO, NODE_115..117 VCOs, NODE_120, NODE_155/157 hit, NODE_173..182
  fire, NODE_279/280 mixer).
* Analog part is stepped at 750 kHz (12 MHz / 16), well above MAME's 48 kHz,
  so 555 edges do not need MAME's sub-sample interpolation.
* Voltages are signed 40 bit fixed point, 32 fraction bits. Each RC step is
  `v += (target - v) * k` with `k = 1 - exp(-dt/RC)` — the same formula MAME
  uses — computed with one 27x27 multiplier.
* The hit band pass uses MAME's bilinear coefficients, rewritten as
  `y = 2*y1 - y2 + c1*y1 + c2*y2 + b0*(x - x2)` so the tiny coefficients keep
  their precision at 750 kHz, and keeps MAME's output clipping at the op-amp rails.
* Pitch counter runs at exactly 1.536 MHz (fractional divider from 12 MHz);
  the 74393 bits are averaged over each step (like MAME's "energy" outputs).
* Moon Cresta hardware games (Port Man, King & Balloon, Moon Quasar, i.e.
  `W_MOONCR`) use MAME's single-stage Moon Cresta mixer; all others use the
  Galaxian two-stage mixer, as in MAME.
* Output is signed 16 bit, 1.0 V at the speaker node = full scale, same as
  MAME's discrete output. `AUDIO_S` is now 1. King & Balloon speech is mixed in
  centred, with saturation.
* `FIRE_TRIM = 0.6` (in `gen_consts.py`): the fire signal reaches the mixer
  through C26, an 18 us high pass, so each 555 edge is a very short spike.
  MAME at 48 kHz loses about 4.5 dB of that spike energy; the 750 kHz model
  keeps it and sounded brighter than MAME. The trim brings the fire level back
  to MAME (2–12 kHz band within 0.5 dB). Set it to 1.0 for the raw circuit.

Old sound files and the FIR/HIT sample ROMs were removed.

## How it was verified

All tools are in `sim/galaxian_sound/` (see the README there).

1. `mame_log.lua` — MAME autoboot script: plays the game automatically
   (coin, start, move, fire) and logs every sound register write with its
   emulated time, while MAME records its own audio with `-wavwrite`.
2. `galsnd_ref.cpp` — double precision C++ port of MAME's discrete nodes.
   Against MAME's WAV: pitch melodies are sample-exact, per 250 ms RMS matches
   (Galaxian and Moon Quasar), so it is a valid golden model.
3. `galsnd_fix.cpp` — bit-exact C++ model of the VHDL (same integers, same
   clock-by-clock timing as the testbench). Needed because GHDL's numeric_std
   multiplies are very slow (2 s of audio takes ~9 minutes).
4. `tb_galaxian_snd.vhd` (GHDL) — RTL output is **bit-identical** to
   `galsnd_fix` on a dense stimulus (8 s of gameplay compressed into 400 ms).
5. RTL model vs MAME, 57 s of Galaxian gameplay, after a MiSTer-like 20 kHz
   output filter, band energy (dB):

   | segment | 20-500 Hz | 0.5-2 kHz | 2-6 kHz | 6-12 kHz |
   |---|---|---|---|---|
   | whole game, MAME / FPGA | -30.7 / -30.6 | -37.3 / -37.3 | -37.8 / -37.3 | -40.0 / -39.9 |
   | swarm only | -31.6 / -31.3 | -39.4 / -39.4 | -43.6 / -43.7 | -52.9 / -53.6 |
   | fire | -33.1 / -33.0 | -35.6 / -35.6 | -34.7 / -34.2 | -37.0 / -36.8 |
   | explosion | -26.0 / -25.8 | -35.0 / -35.0 | -41.0 / -41.0 | -46.3 / -46.6 |
   | melody | -45.7 / -45.7 | -36.6 / -36.6 | -42.3 / -42.3 | -46.8 / -47.3 |

   LFO period for every DAC value matches MAME to 0.1 ms (table above).
   Waveforms are not sample-identical over long times only because free
   running oscillators (and the noise LFSR) start from different phases.
6. `tb_core.vhd` (GHDL) — whole core with the Galaxian ROM, 1 s after reset:
   60 frames (VSYNC watchdog never fired), audio output has no metavalues and
   stays at the quiet level (-1 LSB) with no power-on pop. 1 s takes ~9 min.
7. Quartus 17.0 build: 0 errors, timing met in all corners, 56/112 DSP blocks,
   39 % ALMs.

Status at commit time: the debug build is loaded on MiSTer, and listening tests
against MAME on the real hardware are still pending.

## Notes for later work

* Constants are generated: edit `sim/galaxian_sound/gen_consts.py`, then
  `python gen_consts.py > ../../rtl/galaxian_snd_pkg.vhd`.
  `galsnd_fix.cpp` reads the package, so it follows automatically.
* `O_DBG` / `O_DBG_STEP` on `GALAXIAN_SND` are simulation taps (GHDL 6 on
  Windows could not elaborate VHDL-2008 external names); they are left open in
  the core and removed by synthesis.
* At power-on the output coupling cap is preset to the quiet DC level, so there
  is no "pop" (MAME has one at start-up).
