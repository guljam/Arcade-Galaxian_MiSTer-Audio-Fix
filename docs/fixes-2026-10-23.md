# 2026-10-23 — OSD option for a second Galaxian sound: "Classic (FBNeo)"

## Symptom

After the discrete sound rewrite (see `fixes-2026-10-22.md`), the user
compared the core with a YouTube video of Moon Quasar and with the FBNeo
emulator, and heard a clearly different sound (fire, explosion, and in
Galaxian the swarm rhythm). They asked whether both sound versions could be
offered and selected in the OSD, and what the two versions actually are.

## Cause: there are two Galaxian sound implementations

| | Classic (FBNeo / old MAME) | Discrete (current MAME, this core's default) |
|---|---|---|
| origin | MAME 0.36b11 - 0.133u1 (`src/mame/audio/galaxian.c`, ~2000-2009); FBNeo `src/burn/drv/galaxian/gal_sound.cpp` is a port of it, plus a filtered explosion added by FBNeo in 2025 | MAME 0.133u2 (2009, couriersud) and later, `galaxian_discrete` netlist |
| method | each sound synthesized directly, circuit only approximated | 555 timers, RC networks, op-amp filter, resistor mixer with real part values |
| swarm | 3 square waves, pitch swept linearly 185 -> 93 Hz once per LFO period | 555 pulse waves, control voltage from a 555 sawtooth |
| fire | precomputed 2 s wave (555 + RC model run once at start-up), 0..+max pulses | computed in real time |
| explosion | LFSR noise, volume steps every 3 frames, low shelf 150 Hz + low pass 550 Hz (FBNeo) | noise -> RC envelope -> 168 Hz band pass |

The swarm rhythm differs because the LFO period formula differs. The old
MAME formula is a guess (its comment says "max period: no idea, since I
don't know the max. value for Ra"):

| DAC | 15 | 14 | 13 | 12 | 11 | 8 | 4 | 0 |
|---|---|---|---|---|---|---|---|---|
| discrete (s) | 1.25 | 0.93 | 0.72 | 0.60 | 0.49 | 0.34 | 0.23 | 0.18 |
| classic (s) | 1.22 | 1.16 | 1.07 | 1.02 | 0.92 | 0.73 | 0.38 | 0.08 |

The YouTube video ("Moon Quasar Arcade Emulated M.A.M.E.") is an emulator
recording, not a PCB, and it has the classic character. Moon Quasar never
enables the swarm, so in that game the difference is in fire / explosion /
melody only.

## Hypothesis

Both versions are wanted by players, and neither is proven to be the PCB.
Offering FBNeo's version as an OSD option gives the familiar "emulator"
sound without losing the discrete model. If the FPGA reproduces FBNeo's
integer/float operations in the same order, its output should match FBNeo
sample for sample (except where FBNeo's double rounding is not worth
copying, see below).

## Fix

* New block `rtl/galaxian_snd_fbn.vhd` (+ generated `rtl/galaxian_snd_fbn_pkg.vhd`):
  FBNeo's Galaxian sound at 48 kHz (one sample every 250 clocks of 12 MHz).
  A short state sequence computes each sample in FBNeo's order:
  tone (16 sub steps), explosion (two biquads in fixed point, signals Q20,
  coefficients Q25, one shared 36x27 multiplier), fire (ROM of the 2 s
  wave, 44101 x 10 bit), swarm (3 square waves, frequency swept per frame),
  then FBNeo's x4 gain and 16 bit clipping per channel.
* Frame tick for the swarm sweep and the explosion envelope: rising edge of
  the core's vertical sync (60.6 Hz, 792 samples per frame like FBNeo).
* Explosion trigger: FBNeo triggers on every *write* of 1, so the core gives
  the block a write strobe (`W_HIT_WR`), not only the latch level.
* `rtl/galaxian.vhd`: new input `snd_classic`, both blocks always run and
  `W_AUDIO` selects one. `Arcade-Galaxian.sv`: OSD
  `O7,Sound,Discrete (MAME),Classic (FBNeo)` (status bit 7, default discrete).
* Known, intentional differences from FBNeo:
  * FBNeo adds the noise / fire wave positions in `double`
    (`+= 1/6`, `+= 22050/48000`), so `floor()` sometimes reads the previous
    wave sample (6.5% of noise samples). The FPGA uses exact integer
    positions. This only changes which noise sample is read; not audible.
  * FBNeo starts the swarm sweep only after the game first writes the DAC
    bits; the FPGA uses the current DAC value from reset (start phase only).
  * FBNeo's out-of-range read of the swarm table when the position is exactly
    32.0 reads index 0 here.

## How it was verified

All tools are in `sim/galaxian_sound/`.

1. `fbn_ref.cpp ref`: FBNeo's code ported as-is (float), driven by the MAME
   register logs (`galaxian_writes.txt`, a Moon Quasar log). `fbn_ref pkg`
   generates the VHDL package from the same code (tables, ROM, coefficients).
2. `fbn_fix.cpp`: bit exact model of the RTL plus its testbench, clock by
   clock.
3. `fbn_ref aligned` (FBNeo code, writes and frame ticks moved to the RTL's
   sample boundaries) vs `fbn_fix`, 60 s Galaxian / 90 s Moon Quasar:
   * tone and swarm channels: 100% identical samples;
   * with `FBN_EXACT=1` (exact wave positions): 99.88% / 99.78% identical,
     every remaining difference <= 8 LSB (fixed point biquad rounding);
   * plain FBNeo positions: same RMS and band energy (0.1 dB), noise differs
     by the double rounding above.
4. `tb_galaxian_snd_fbn.vhd` (GHDL) == `fbn_fix`, bit identical, 400 ms dense
   stimulus (`stim_short.txt`).
5. Verilator: `vl_fbn.sh` converts the VHDL with `ghdl --synth` and builds
   `vl_tb_fbn.cpp`; output == `fbn_fix`, bit identical, 60 s Galaxian and
   90 s Moon Quasar (about 1 min each).
6. Full core with the Galaxian ROM (`tb_core.vhd`, `CLASSIC=1`,
   `STUB_DISCRETE=1` build replaces the discrete block by a silent stub to
   make GHDL fast enough, ~4.4 min per second of game time): 2 s with coin
   at 0.3 s and start at 0.7 s, 119 frames, VSYNC watchdog never fired, no
   metavalues. The output is silent, as expected: in the first ~2 s the game
   only initializes the sound registers (all off; in the MAME log the game
   sound starts after 3 s), and reaching game play would take ~26 min of
   simulation, over the 10 min limit. The sound data path itself is covered
   by steps 3-5; the core level run checks the wiring and that nothing
   breaks.
7. GHDL output == Verilator output on the 400 ms stimulus (checks the
   `ghdl --synth` conversion used for Verilator).
8. Quartus 17.0 debug build: 0 errors, timing met in all corners (worst
   slack +0.224 ns), 40 % ALMs, 23 % block memory (186 M10K, of which the
   fire ROM 441,010 bits), 59/112 DSP blocks.
   Note: the first build read the ROM straight from the package constant and
   Quartus built it from logic (+3,900 LUTs, 46 % ALMs). Reading it from a
   signal initialized with the constant and `romstyle "M10K"` makes Quartus
   infer an altsyncram. `vl_fbn.sh` converts a copy that reads the constant,
   because `ghdl --synth` writes a signal's initial value as one 441,010 bit
   Verilog literal that Verilator cannot handle.

Status: the debug build is on MiSTer as `Galaxian_20261023.rbf`; listening
tests on the real hardware (OSD Sound = Classic (FBNeo)) are pending.

## Notes for later work

* Constants and the fire ROM are generated:
  `fbn_ref.exe pkg > ../../rtl/galaxian_snd_fbn_pkg.vhd` (in `sim/galaxian_sound`).
* `O_SAMPLE` on `GALAXIAN_SND_FBN` is only for the testbench watchdog; it is
  left open in the core.
* Both sound blocks always run; the OSD only selects the output, so it can
  be switched during play.
